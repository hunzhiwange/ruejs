## 测试计划

- 行为：测量器对固定样本产生稳定 schema，并能拒绝缺失指标或超预算结果。
- 失败验证测试：`scripts/__tests__/reactive-kernel-performance.spec.ts` 中新增“验证完整报告并拒绝超预算数据”。
- 失败验证命令：`pnpm exec vitest run scripts/__tests__/reactive-kernel-performance.spec.ts --project unit`
- 预期失败原因：测量脚本、schema 和预算检查器尚不存在。
- 通过验证命令：`pnpm exec vitest run scripts/__tests__/reactive-kernel-performance.spec.ts --project unit && node scripts/reactive-kernel-performance.mjs --output temp/performance/reactive-baseline.json`
- 模拟策略：单元测试只模拟计时输入验证预算算法；正式报告运行真实 Runtime、GC 可用时记录 GC 数据但不得伪造。

## 步骤

1. 先编写报告 schema、预算失败和确定性统计测试。
2. 运行失败验证并保存预期失败摘要。
3. 实现测量器、工作负载、预热/多轮中位数和 JSON 输出。
4. 生成当前实现基线与明确预算；预算允许测量噪声但不允许明显回退。
5. 运行单测与一次完整基准，审查报告无空指标。

## 验证

- 运行：`pnpm exec vitest run scripts/__tests__/reactive-kernel-performance.spec.ts --project unit`
- 运行：`node --expose-gc scripts/reactive-kernel-performance.mjs --output temp/performance/reactive-baseline.json`
- 预期：测试退出码 0；报告包含全部工作负载、环境元数据和有限数值；当前实现通过初始预算。
- 所需证据：失败测试摘要、通过测试数量、报告路径、每类工作负载中位数和堆增量、预算检查退出码。
