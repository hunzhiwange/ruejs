## 上下文

- `runtime-core/compiled.ts` 当前维护独立 `DependencyRecord/EffectRecord/pendingEffects`。
- 保留 owner/lifecycle/setup cache 和 compiler render scheduler，但 Signal/Effect/Batch 必须委托单一 kernel；同模块不能出现分裂图。

## 测试计划

- 行为：public signal、compiler signal 和混合组件相互订阅、批处理和释放时只出现一套 Graph 统计。
- 失败验证测试：新增“compiler/public 跨入口互操作且共享 node/link 计数”和“owner dispose 清除统一图节点”。
- 失败验证命令：`pnpm exec vitest run packages/runtime/__tests__/reactive-kernel.entry-interop.spec.ts packages/runtime/__tests__/runtime-architecture.spec.ts --project unit-jsdom`
- 预期失败原因：compiler entry 当前使用独立 Set 记录，无法共享 Graph 计数和调度所有权。
- 通过验证命令：`pnpm exec vitest run packages/runtime/__tests__/compiler-runtime.compact-kernel.spec.ts packages/runtime/__tests__/reactive-kernel.entry-interop.spec.ts packages/runtime/__tests__/runtime-architecture.spec.ts --project unit-jsdom`
- 模拟策略：构建并加载真实内部入口，不 mock kernel。

## 步骤

1. 添加跨入口读写、调度、owner 释放和单图统计失败测试。
2. 抽取 compiler 所需的最小 kernel 工厂与共享实例。
3. 将 compiled Signal/Effect/Batch 改为薄转发，保留 owner/lifecycle 层。
4. 删除 `DependencyRecord` 等第二套订阅实现和重复调度队列。
5. 运行 runtime size audit，避免统一后把完整 JS facade 拉入 compiler entry。
