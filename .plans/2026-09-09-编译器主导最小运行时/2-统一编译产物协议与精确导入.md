## 上下文

- 当前 capability 表有 Compiled/Vapor tier，并按模块最高 tier 升级共享能力，容易把完整 runtime 拉入。
- 新协议按 dom、reactive、block、component、list、events、builtin、hydrate、ssr 分类；一个 helper 只能有一个实现入口。

## 测试计划

- 行为：编译产物只导入实际使用的 capability，混合语法不会升级到聚合 runtime。
- 失败验证测试：新增静态 JSX、state 文本、事件、组件、列表、builtin 的 import snapshot。
- 失败验证命令：`pnpm --filter @rue-js/swc-plugin-rue test`
- 预期失败原因：现有路由仍输出 compiler/component/builtins 聚合入口和 tier 升级。
- 通过验证命令：`pnpm --filter @rue-js/swc-plugin-rue test && pnpm run check:compiler-runtime-boundary`
- 模拟策略：使用真实 SWC AST 与生成源码快照。

## 步骤

1. 先写精确 import snapshot 和重复 helper 去重测试。
2. 以 capability→唯一子路径映射替代模块 tier 聚合。
3. 为最小入口增加 package exports，禁止入口互相转发到聚合 index。
4. 明确未编译 JSX/未知 runtime helper 为编译错误，不回退 Vapor 或 public runtime。
5. 构建插件并验证现有测试只因后续 ABI 尚未迁移而失败时，记录精确调用点。
